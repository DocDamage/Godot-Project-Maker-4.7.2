## Result

**All 30 selected inputs completed analysis without an error, but this is not 30 supported packs.** There were 443 input image files and 13,924 catalog image entries after cutting and terrain generation. Of 13,645 active entries, 3,974 (29.1%) were marked Auto-detected or Confirmed and 9,671 (70.9%) needed review. Another 279 image entries were unused. These are confidence/workload counts, not measured accuracy.

The agent inspected 109 selected entries beside their source overviews: **55 agreed on the checked fields, 27 required corrections, and 27 remained unresolved**. Eleven correction cases were already marked Auto-detected or Confirmed. This deliberately probes weak entries and role diversity; its error rate must not be extrapolated to the collection. Every decision and its checked fields are in the JSON.

Three assets-only projects were generated, validated, painted and furnished using the existing editor probe. All built, but LPC Floors had 128 terrain mismatches and the isometric floor render contained magenta mask cells. The farm sample had zero reported holes/mismatches and visible buildings, crops and props. None of these checks certify a whole pack.

## Method and limits

* Selected 28 top-down inputs plus two isometric extensions from seven library folder groups. The folder names identify local source groups, not verified publisher identities. This is a convenience sample of the owner's collection; popularity, purchase status and previous development use were not established.
* Excluded `_organized_sprites`, `_organized_sprites_vision_required`, logs, Claude outputs and unrelated application code. Opened the actual RAR payloads inside the two Screaming Brain wrapper folders; a wrapper containing only archives itself yielded no images.
* Used the existing `archive.open_pack`, `inventory.build_inventory` and `catalog.assemble` pipeline with normal descriptive pack IDs. Used isolated settings/cache/profiles on F:, no installed profiles, no learned corrections and no vision. An initial short-ID pilot was discarded because removing pack-name clues changes classification.
* Reported timing is observed wall time with mixed/warm caches; the pilot and earlier pack reads warmed some caches. No cold-performance conclusion is drawn.
* Visually selected up to four distinct active entries per pack: lowest confidence, highest confidence, a different role when available, then a midpoint/next entry. Inspected all six contact sheets, enlarged the Modern Interiors character strips, and inspected the three editor renders. Acceptable means only the recorded checked fields agreed.
* **No baseline audit edits were applied.** The corrections column counts errors found in the selected entries, not a complete pack's required edits. Full audit counts, owner approval and wizard-to-first-paint timing remain unmeasured.
* License values are the reader's labels from local files, including parent-folder text. Unknown labels stay unknown; a name containing RPG Maker or LPC does not establish its layout or license.
* Source integrity: rehashed all seven input archives and 292 accepted files of folder inputs after the study; every hash matched its initial inventory. Source art was neither edited nor committed.

## Repeat the baseline

Use Python 3.12 from the project venv. Set `RPGGEN_CACHE_DIR`, `TEMP` and `TMP` under an F: scratch directory. For each `packs[].relative_path` in the JSON, run the normal analyzer with the original pack name:

```powershell
$env:RPGGEN_CACHE_DIR = "F:\rpggen_scratch\coverage_repeat\runtime"
$env:TEMP = "F:\rpggen_scratch\coverage_repeat"
$env:TMP = $env:TEMP
New-Item -ItemType Directory -Path $env:TEMP -Force | Out-Null
& .\.venv\Scripts\python.exe -m rpggen analyze "G:\All 2D Assets Stay Here\RPGMAKERASSETS\lpc-floors.zip" --out "$env:TEMP\lpc-floors.json" --json
```

The exact 30-pack manifest and the batch runner are also retained in the scratch directory. Counts can be checked from saved catalogs: image entries outside UNUSED/MISSING are active; AUTO_DETECTED/CONFIRMED are confident; the remainder are NEEDS_REVIEW.
