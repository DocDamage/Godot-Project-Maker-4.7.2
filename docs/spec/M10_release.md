# M10 — Release Hardening

**Goal:** a signed, installable 1.0 that a stranger can download, run on an unseen pack, and get a working project from. It ships with documentation, diagnostics, the profile registry and an export check.

---

## T10.01 — Diagnostic bundles

**Depends on:** M9 gate
**Files:** `rpggen/core/diagnostics.py`, GUI buttons (results page and error dialog), `rpggen/cli.py` (`diagnose`), tests

`make_bundle(target_or_failed_dir: Path, out_zip: Path) -> Path` creates a zip containing:
* `system.json`: OS version (`platform.platform()`), Python version, rpggen version, Godot version and path (with the user name replaced by `<user>`), and the locale.
* `config.json`, `asset_catalog.json`, `ownership_ledger.json`, `build_state.json` and `results/*.json`, all copied.
* `logs/*.log`: copied with **redaction**. Replace the user's home path with `<home>`, replace the user name with `<user>`, and cap each log at its last 5 MB.
* `assets_manifest.json`: for every catalog asset, `{id, path, sha256, w, h, size}`. **No image bytes.**
* `README.txt`: explains what is inside and that no art is included.

Tests: the bundle contains no files with image or audio extensions; the redaction is applied.

## T10.02 — Packaging

**Depends on:** T10.01
**Files:** `packaging/rpggen.spec` (PyInstaller), `packaging/installer.iss` (Inno Setup), `packaging/version_info.txt`, `.github/workflows/release.yml`

* PyInstaller in **one-folder mode**, with `--windowed` for `rpggen.exe` (GUI) plus a second console entry, `rpggen-cli.exe`.
* Data files to include: `godot_templates/` (excluding `tests/` and `.godot/`), `sample_pack/`, `rpggen/schema/*.json`, `rpggen/gui/style.qss` and the docs.
* Use the PySide6 hooks; exclude unused Qt modules (QtWebEngine, Qt3D, QtMultimedia unless needed) to keep the size down.
* `multiprocessing.freeze_support()` must already be in place (T3.02).
* Inno Setup installer: per-user install by default (no admin needed), a Start-menu shortcut, an uninstaller, and the license page shows MIT plus the third-party notices (`THIRD_PARTY_NOTICES.md` lists PySide6/Qt LGPL, Pillow, numpy, py7zr, jsonschema and mutagen, each with its license text or link).
* Also produce a portable zip of the one-folder build.
* Release workflow on tag `v*`: build both, sign them (T10.03), attach them to the GitHub Release with SHA-256 sums.

**Smoke test of the frozen build in CI:** run `rpggen-cli.exe generate --pack sample_pack --target out --godot $RPGGEN_GODOT` and expect exit code 0.

## T10.04 — Community profile registry

**Depends on:** T3.14
**Files:** a separate repo `rpggen-profiles` (structure below); `rpggen/core/profile_registry.py`; GUI "Find profile online" button

Registry repo layout:
```text
profiles/<profile_id>.rpgprofile.json
index.json            ← generated by CI: [{profile_id, title, fingerprint_hashes: [...], author, license}]
.github/workflows/validate.yml   ← schema-validates every profile, regenerates index.json
CONTRIBUTING.md
```

* The client downloads `index.json` from the repo's raw URL **only when the user clicks the button**. That is the only network call in the app besides update checks, which are also user-initiated.
* Matching uses the local inventory's hashes; candidate profiles are those whose fingerprint has at least 50% overlap. The user picks one, the client downloads the profile file, validates it against the schema, and installs it to the profiles dir.
* Profiles are data only and are schema-validated. Reject anything that doesn't validate. Never execute anything from a profile.
* License: profiles are contributed under CC0-1.0, enforced by the schema's `license` const.

## T10.05 — Export preset and export test

**Depends on:** M9 gate
**Files:** `builder/recipes/export_preset_recipe.gd`, `rpggen/core/export_check.py`

* Write `export_presets.cfg` with one preset, `Windows Desktop`, exporting to `export/windows/<project_slug>.exe`, with `embed_pck = true`. ⚠ VERIFY the keys by creating a preset in the editor once and copying its structure. Because `export_presets.cfg` is an INI-like text file, **this is the one place where writing engine config text is acceptable**. Generate it from a verified template in `godot_templates/project_files/export_presets.template.cfg`.
* Export check (optional phase, enabled when export templates are installed for 4.7.2, by checking the templates directory under `%APPDATA%/Godot/export_templates/4.7.2.stable/`): run `godot --headless --path <staging> --export-release "Windows Desktop" <tmp>/test.exe`, expect exit code 0 and a non-empty file, then delete it. If the templates are missing → add an info issue (new code **ENV-010** `"Export templates for 4.7.2 not installed; export check skipped."`) and skip.

## T10.09 — Held-out validation (Definition of Done)

**Depends on:** everything
* The human maintainer selects **5 packs not used during development**: at least 2 commercial, 1 RPG Maker format, 1 with Tiled metadata, and 1 "messy" pack.
* For each pack and each archetype, record:
  * time to first paint (wizard start → painting tiles in Godot)
  * the number of manual audit edits
  * whether generation passed
  * any bugs found
* Every bug is fixed or ticketed. The release can ship when all 10 runs pass and the median time to first paint is under 10 minutes.
* Publish the coverage study results (ARCHITECTURE §51) in `docs/coverage.md`.
